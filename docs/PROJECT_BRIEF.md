# Neurolume 项目简报（v4 · 单机 Mac 版）

> 这是项目的原始需求说明，PLAN.md 由它细化而来。需求有变化时先改这里，再改 PLAN.md 和 docs/DECISIONS.md。

## 目标
在一台 MacBook Pro（M5 Max，128GB 统一内存）上，做一个本地编程模型 Neurolume。所有组件都在这台 Mac 上运行，不跨机器同步。
我平时用已登录的 Claude Code 和 Codex 解决问题；Neurolume 在后台观察学习，逐渐掌握我的项目约定和习惯；用 3D 大脑 UI 展示它思考和成长时的真实内部信号。

## 原则
1. 先证明"学习有效"，再做漂亮的 UI。每种学习手段（RAG、规则、LoRA）都必须用评测数据证明比不用更好，否则不上线。
2. 评测集和已验证样本库是核心资产；底座模型可替换，换底座时用样本库重新训练。
3. 可视化必须对应真实信号；界面注明"脑电波"是风格化呈现，不是真实脑电。
4. 资源克制：推理优先，后台任务随时可暂停，磁盘有预算。

## 工作方式
- 按里程碑推进，满足"验收标准"后停下来给我演示，再继续。
- 所有版本和 API 先联网核实再用，不凭记忆：mlx-lm 对目标模型的推理与 LoRA 支持、MLX 内存限制 API、Claude Code hooks 与会话记录格式、Codex 会话记录格式。
- 不确定的技术选择给 2-3 个方案和推荐，由我决定；决定记入 docs/DECISIONS.md。
- 删除文件的操作先 dry-run 并写日志。

## 系统架构

```
  ┌──────────── 我的日常工作 ────────────┐
  │ Claude Code / Codex  →  我的 git 仓库 │
  └──────┬───────────────────┬──────────┘
         │会话记录/hooks      │post-commit hook
         ▼                   ▼
  ┌─────────────── observer 观察者 ───────────────┐
  │ 解析会话 → 对齐 diff → 验证 → 脱敏 → 样本库    │
  └──────────────────────┬────────────────────────┘
                         ▼
  ┌─────────────── learner 学习器 ────────────────┐
  │ 影子对照(worktree) → RAG → 规则 → LoRA         │
  │ 评测闸门(dev + holdout) → 版本管理/回滚        │
  └──────────────────────┬────────────────────────┘
                         ▼ 加载适配器
  ┌──────────── neurolume-server 推理服务 ───────────┐
  │ mlx-lm 模型 + 层 hook                          │
  │ OpenAI 兼容接口 ← 编辑器 / OpenCode / 前端聊天  │
  │ WebSocket 广播：token事件 / 学习事件 / 快照     │
  └──────────────────────┬────────────────────────┘
                         ▼
  ┌─────────────── 前端 Web UI ───────────────────┐
  │ 3D大脑 · 学习面板 · 时间轴 · 存储页 · 负载页    │
  └───────────────────────────────────────────────┘
  scheduler 调度器：所有后台任务的唯一入口（优先级、空闲检测、内存/磁盘预算）
```

## 组件
- **neurolume-server**（Python）：mlx-lm 加载模型和当前 LoRA 适配器；OpenAI 兼容接口（/v1/chat/completions，支持流式）；内部 hook 各层，把汇总后的激活通过 WebSocket 广播。任何调用都会驱动大脑。
- **observer**：git post-commit hook + Claude Code hooks（会话结束触发）+ Codex 会话记录解析，产出学习样本。
- **learner**：影子对照、RAG 知识库、规则沉淀、LoRA 训练、评测闸门、版本管理。
- **scheduler**：优先级、空闲检测、资源预算；所有重任务都必须经过它。
- **前端**：React + Vite + TypeScript + react-three-fiber。大脑、学习面板、版本时间轴、存储页、负载页、简单的本地聊天页。本地答不了时一键复制"交给 Claude Code/Codex 的任务描述"（附本地失败的尝试）。
- **存储**：SQLite + sqlite-vec，统一可配置的数据目录。
- 后台服务用 macOS launchd 管理，一键启停；所有配置集中在一个配置文件。

## 底座模型
候选：Qwen3.6-27B（主选，稠密混合架构，8bit 约 29GB）、Devstral Small 2（对照，24B 标准注意力，4bit 约 15GB）。Qwen3.8-27B 与 3.6 同结构，训练工具成熟后再升级。不考虑 4bit 超过 100GB 的模型。详见 docs/DECISIONS.md D13。
先核实各模型的层结构：部分新模型是混合架构，线性注意力层没有注意力矩阵，hook 和可视化要按层类型分别处理；MoE 模型要能取到专家路由。
用评测集横向比较：通过率、tokens/s、峰值内存、LoRA 训练一步的耗时和内存。

## 评测集
- 从指定仓库的 git 历史自动挖掘：找同时修改源码和测试的提交，把源码回退到父提交作为题目，用提交后的测试判分。生成后由我审核入库。
- 支持手写任务，格式相同。
- 分 dev（日常比较）和 holdout（只用于上线闸门）。holdout 内容永远不进训练样本和知识库，用内容哈希保证。
- 判分在临时目录或 git worktree 中进行，有超时和资源限制。

## 观察与样本
1. 只观察配置中列出的仓库。
2. 用会话中的文件编辑记录对齐 diff，区分云端 AI 的改动和我的手改。
3. 样本 = 任务描述 + 相关上下文 + 最终保留的修改 + 验证结果。只有测试通过、被我提交、7 天内未被回滚的才标为"已验证"，才能进训练。
4. 脱敏：密钥、令牌、绝对路径、邮箱等。永远不读取凭证：~/.claude/.credentials.json、~/.codex/auth.json、.env 文件、macOS 钥匙串（不得调用 security 等命令）。
5. README 提醒自行核对 Anthropic/OpenAI 条款中关于用输出训练模型的限制；默认优先沉淀"项目约定和踩坑经验"类知识。

## 学习
- **影子对照**：云端完成任务后，本地模型在 git worktree 中独立重做同一任务（不碰真实文件），跑相同测试。通过=已掌握；失败=进入学习队列，记录"意外程度"。
- **第一层 RAG**：样本即时入库；报告有/无 RAG 的影子通过率。
- **第二层规则**：同类错误出现 3 次以上生成规则草稿，经我批准后加入系统提示。
- **第三层 LoRA**：已验证样本攒够一批后训练，混入旧样本回放防遗忘；dev 和 holdout 都不低于当前版本才上线，否则自动回滚。只存适配器，记录样本来源、超参、分数。

## 资源与磁盘
- 有推理请求时暂停后台任务；重任务只在空闲 N 分钟、接电、温度和内存压力正常时运行，同时只跑一个；影子任务每日有次数上限；"静默模式"一键暂停所有学习。
- 内存预算可配置，使用 MLX 的内存限制接口（先核实）；训练前检查可用内存，不足则推迟。
- 激活采集只抽样（每 N 个 token）、只算范数，在 GPU 上汇总后再取回；"轻量/完整"两档；前端限帧。
- 磁盘：总预算 + 后台 GC + 80% 告警；适配器保留最近 N 个 + 最佳 + 里程碑版本；worktree 用完即删，启动时清理残留；原始会话摘录 30 天过期；样本去重压缩；激活只存汇总；模型缓存目录统一。存储页一键清理（先 dry-run）。

## 大脑可视化
- 脑区 = 层段（浅/中/深）；区域内神经簇 = 注意力头 / MLP / 专家；不同层类型用不同视觉样式。
- 思考：按 token 事件高亮激活最强的层和头；类 EEG 波形由各层激活能量生成。
- 学习：按 LoRA 各层 ΔW 范数让区域发光、连线变粗；意外程度越高越亮。
- 重要性：各层梯度范数；消融实验（关闭某层或头，看 dev 分数变化）；稀疏自编码器特征留作后期。
- 时间轴：拖动对比不同版本的大脑差异和分数曲线。
- 观察者检测到 Claude Code/Codex 会话进行中时，大脑显示"观察中"。
- 数十亿权重不逐个画，一律按层/头/聚类汇总。

## 里程碑
